# あつ杯 GASバックエンド

スプレッドシートを正本として、`data/*.json` と同じ形のJSONを生成する。

## 現在の段階: Phase 1（読み取りのみ）

`Code.gs` には **書き込みAPI（`doPost`）がまだ無い**。
そのためデプロイしても、外部から書き換えられる口は存在しない。安心してセットアップしてよい。

| Phase | 内容 | 状態 |
|---|---|---|
| 1 | スプレッドシート作成・シート↔JSON変換・`doGet` | ✅ このドキュメントの範囲 |
| 2 | Googleログイン認証 + `doPost`（書き込み）+ GitHubへのpush | 未着手 |
| 3 | アプリ本体を GitHub PAT 方式から切り替え | 未着手 |

## Phase 1 セットアップ手順

### 1. スプレッドシートを作る

1. Googleドライブで新しいスプレッドシートを作成する（名前は「あつ杯データ」など）
2. URLから **スプレッドシートID** を控える
   `https://docs.google.com/spreadsheets/d/`**`ここがID`**`/edit`

### 2. Apps Script プロジェクトを作る

スプレッドシートのメニューから **拡張機能 → Apps Script** を開く。
（こうするとスプレッドシートに紐づいたプロジェクトになる）

エディタの `コード.gs` の中身を全部消し、このリポジトリの **`gas/Code.gs` の中身を丸ごと貼り付けて保存**する。

### 3. スプレッドシートIDを登録する

エディタ左の **⚙️ プロジェクトの設定 → スクリプト プロパティ** で追加：

| プロパティ | 値 |
|---|---|
| `SPREADSHEET_ID` | 手順1で控えたID |

### 4. シートを作る

エディタ上部の関数選択で **`initSheets`** を選び、実行する。

- 初回実行時にGoogleの承認画面が出る → 自分のアカウントを選び、許可する
  （「このアプリはGoogleで確認されていません」と出たら、**詳細 → 安全でないページに移動** で進む。自分で書いたスクリプトなので問題ない）
- 実行ログに「作成したシート: users, tournaments, entries, matches, admins, audit」と出れば成功

⚠️ この関数は**日時やIDが日付として自動変換されないように、文字列列を「書式なしテキスト」に設定**している。
シートを手作業で作らずに必ずこの関数で作ること。

### 5. 既存のユーザー15人を投入する

**`seedUsers`** を実行する。ログに「15人を投入しました。」と出れば成功。

（`users` シートに既に行がある場合は、誤って上書きしないよう何もしない設計）

### 6. 正しく読めているか確認する

**`dumpUsersJson`** を実行し、実行ログに出たJSONをコピーして、
リポジトリの `data/users.json` と一致するか比較する。

続けて **`selfTestRoundTrip`** を実行する。
「users: ✅ 一致」と出れば、シート→JSON→シート→JSON で情報が失われていない。

### 7.（任意）Webから読めるか確認する

`doGet` をブラウザから叩いて確認したい場合のみ：

**デプロイ → 新しいデプロイ → 種類の選択「ウェブアプリ」**

| 項目 | 設定 |
|---|---|
| 次のユーザーとして実行 | 自分 |
| アクセスできるユーザー | 全員 |

発行されたURLに `?table=users` を付けて開くとJSONが返る。

> **なぜ「アクセスできるユーザー: 全員」で安全なのか**
> Phase 1 の `Code.gs` には読み取り（`doGet`）しか実装されていないため、書き込まれる余地が無い。
> ただし **Phase 2 で `doPost` を追加した瞬間、この設定のままでは「URLを知る全員が書き込める」状態になる。**
> そのため Phase 2 では必ず、GAS側でGoogleログインのIDトークンを検証し `admins` シートと照合する認証を同時に入れる。

## 🔴 データの向きと、移行時の必須手順

このシステムは **「シートが正本、GitHubはその書き出し先」** という一方向で動く。

```
スプレッドシート ──書き出し──▶ GitHub data/*.json ──▶ アプリが読む
```

したがって **GitHub側にだけ存在するデータがある状態で書き込むと、シートの内容で上書きされて消える。**

以下のタイミングでは、**書き込み前に必ず `importFromGitHub()` を実行**すること。

- スプレッドシートへの移行時（初回）
- 旧方式（アプリから直接GitHubへPATで書く）で更新した後
- 他の誰かがGitHub上で `data/*.json` を直接編集した後

### 手順

1. **`compareWithGitHub()`** を実行（変更なし・確認のみ）
   `⚠️ GitHubにのみ存在` と出た行があれば、取り込みが必要
2. **`importFromGitHub()`** を実行
   GitHubの内容でシートを上書きする（上書き前の内容は実行ログに出るので復元可能）
3. もう一度 `compareWithGitHub()` で `✅ id集合は一致` を確認

なお `exportTables_()` には安全装置があり、**シートが空なのにGitHubにデータがある場合は書き出しを中断**する。
ただしこれは「シートが完全に空」のケースしか検知できないため、上の手順を省略しないこと。

## シート構成

`data/SCHEMA.md` と1対1で対応する。**列名はスキーマ通りにすること**（`Code.gs` は列名でヘッダを引き当てるため、列の並べ替えは可能だが改名は不可）。

| シート | 用途 |
|---|---|
| `users` | ユーザーマスタ |
| `tournaments` | 大会 |
| `entries` | 大会参加者（順位・勝数） |
| `matches` | 対戦カード |
| `admins` | **書き込みを許可するメールアドレス**（Phase 2で使用） |
| `audit` | 誰がいつ何を更新したかの記録（Phase 2で使用） |

### 手で編集するときの注意

運用上は「アプリ経由が主、シートは閲覧・緊急修正用」だが、手で直す場合：

- **`matches` の `player1SrcIndex` / `player2SrcIndex` を空にしないこと。**
  2回戦以降で「前ラウンドのどのカードの勝者か」を保持しており、
  これが欠けると後から勝敗をやり直したときに勝者が誤った枠へ入る
- `id` は他テーブルから参照されている外部キー。書き換えると紐付けが切れる
- ユーザーを消したい場合は行削除ではなく `archived` を `TRUE` にする（過去の戦績を保持するため）
- 大会を消したい場合も同様に、`tournaments` の行削除ではなく `archived` を `TRUE` にする（`entries`/`matches`はそのまま残す）。アプリの削除ボタンからも同じ操作ができる

### 🔴 列を追加するときの必須手順（Code.gsのSCHEMAに列を足す場合）

`Code.gs`の`readSheet_()`は、`SCHEMA`で定義した列名をシートの**実際のヘッダ行から名前で引き当て**、見つからなければ即座に例外を投げる。つまり、**コード側のSCHEMAに列を追加しただけでは動かず、シート側にも同名の列が無いと、そのテーブルに関わるAPI呼び出しが全て失敗する**。

1. まずスプレッドシートの対象シートを開き、新しい列を**既存データがある列の一番後ろ**に追加する（途中に挿入すると既存行の値が1列ずつズレる）
2. 列名は`Code.gs`の`SCHEMA`と完全一致させる（大文字小文字・スペルとも）
3. その後で、更新した`Code.gs`をデプロイする（順序が逆だと、デプロイ直後から大会/ユーザー関連の操作が全て失敗し始める)
4. 既存行はその列が空欄になるが、`bool`型の空欄は自動的に`false`として読まれるため、データ破損にはならない

**2026-07-27の`tournaments`への追加例**: `archived`・`isOfficial`・`isRestricted`の3列を`status`の後ろに追加（`data/SCHEMA.md`参照）。

## 関数リファレンス

| 関数 | 用途 |
|---|---|
| `checkConfig()` | Script Properties の不足・シート・admins・GitHub到達性をまとめて検査 |
| `compareWithGitHub()` | **変更なし。** シートとGitHubの差分を報告する |
| `importFromGitHub()` | GitHubの `data/*.json` でシートを上書きする（移行・復旧用） |
| `initSheets()` | 6シートを作成し、ヘッダと書式を設定（初回のみ） |
| `seedUsers()` | 既存の15人を `users` へ投入（初回のみ・`importFromGitHub()` を使うなら不要） |
| `dumpUsersJson()` | `users` をJSONでログ出力（`data/users.json` との比較用） |
| `selfTestRoundTrip()` | シート→JSON→シート→JSON で内容が変わらないか検証 |
| `doGet(e)` | `?table=users` で単一、パラメータ無しで全テーブルをJSONで返す（**検証用**） |

`doGet` はデバッグ用であり、**アプリ本番の読み込み経路ではない**。
本番の読み込みは GitHub Pages の静的 `data/*.json` を使う（高速・GASクォータを消費しない・ログイン不要）。
